# Human Plus

**Неофіційний клієнт для HUMAN Школа.** Усе важливе для учня на одному екрані: розклад дня, що задано, що не виконано, оцінки.
Лише читання. Без здач завдань, без чужих даних, без телеметрії.

> «Plus» означає **надбудову над HUMAN: зручніший погляд на ті самі дані**, а не платний тариф і не офіційне розширення.
> Застосунок не пов'язаний із компанією HUMAN. Ми свідомо не використовуємо логотип і бренд HUMAN.

![Сьогодні: таймлайн уроків, клік розкриває заняття й завдання](docs/img/dark-glass-today.png)

## Проблема

В оригінальному інтерфейсі, щоб дізнатися, що задано на завтра, треба відкривати кожен урок окремо. Завдання розкидані за днями й предметами,
невиконане легко пропустити, а текст завдання, посилання й фото ховаються за двома-трьома кліками.

## Що робить Human Plus

- **Сьогодні:** привітання, таймлайн уроків із підсвіченим поточним уроком і відліком до наступного. **Клік по уроку** розкриває «Заняття» (матеріали уроку)
  та «Завдання» (що задано на цьому уроці) з повним змістом.
- **На наступний урок:** для кожного предмета найближчий урок і невиконане ДЗ до нього, окремий блок «На завтра».
- **Усі завдання:** фільтри «Невиконані / Усі / Здані», предмет, групування за датою чи предметом, прострочене виділене, розгортання на місці.
- **Розклад:** тиждень із позначкою поточного часу, з урахуванням скасованих уроків і замін.
- **Оцінки** за предметами.
- **Увесь вміст усередині застосунку:** текст, заголовки, **фото**, **посилання** (картка з назвою й доменом, відкривається в браузері за кліком),
  **файли** (зберігаються в «Завантаження» за кліком), формули й таблиці. Жодних кнопок «Відкрити в Human».
- **Міні-режим «Що задано на завтра»:** це те саме вікно, що стає малим, поверх інших, із регульованою прозорістю (Ctrl+Shift+H).
- Лічильник невиконаного в треї та на панелі завдань, сповіщення «Завтра дедлайн» раз на день (можна вимкнути).
- Світла й темна теми, акцентний колір і кольори статусів на вибір, «скляні» ефекти (з автоматичним запасним режимом без прозорості).
- Офлайн: показуються збережені дані з позначкою; миттєвий старт із кешу, оновлення у фоні.

## Чого застосунок **не** робить

- Не здає завдань, не змінює статусів, не пише повідомлень: до HUMAN іде лише `GET`.
- Не читає й не зберігає пароль чи токени: ви входите самі на справжній сторінці HUMAN всередині вікна.
- Не бачить чужих даних: лише акаунт учня, що увійшов. Для вчителя й будь-якої іншої ролі показується «Додаток доступний лише для учнів».
- Не збирає телеметрію й не звертається нікуди, крім `*.human.ua`.

## Як це працює

```
вікно (src/app.js, ванільний JS)  ←IPC→  main.js  →  session persist:human  →  api.human.ua / files.human.ua
        │ лише відмальовування               │ перевірка ролі, кеш, запити (лише GET)
        └ model.js (вибірки)                 └ service.js → api.js / blocks.js / normalize.js
```

1. Ви входите на сторінці HUMAN (вона відкривається всередині вікна); сесія живе у стандартному сховищі Electron.
2. `main.js` бере `uid` із куки `last-sub-client-id`, перевіряє роль (`system/info`) і лише для учня завантажує календар та завдання.
3. `normalize.js` перетворює відповіді на внутрішню модель (`Lesson`, `Task`, `Grade`); `blocks.js` — вміст завдань на безпечні блоки.
4. Вікно (без доступу до мережі, суворий CSP) лише показує дані; зображення й файли завантажує main-процес.

Усе, що знає про формат HUMAN, зосереджено в `src/api.js`, `src/blocks.js`, `src/normalize.js`. Результати розвідки API — у [NOTES.md](NOTES.md).

## Приватність

Кеш лежить лише локально, паролі й токени не зберігаються, застосунок нікуди не надсилає дані. Докладніше — [PRIVACY.md](PRIVACY.md).
Кнопка **«Вийти й стерти дані»** прибирає куки, сховище сесії та кеш.

## Відповідальне використання API

Один запуск — **6 запитів** (перевірка ролі, календар на 7 тижнів, чотири категорії завдань). Оригінальний сайт при відкритті сторінки розкладу робить **7**
(виміряно), а перегляд тижня день за днем додає ще. Вміст завдань підвантажується лише за потреби й кешується; поважаємо `429`/`Retry-After`,
використовуємо експоненційну затримку з джитером, не більше 4 одночасних запитів, автооновлення зупиняється після серії збоїв.
Прозорий `User-Agent`: `HumanPlus/<версія> (unofficial; read-only; <контакт>)`. Усі звернення — у [docs/API-USAGE.md](docs/API-USAGE.md).

Контрольні суми SHA-256 — в описі релізу.

### Попередження Windows SmartScreen

Застосунок **неофіційний і не підписаний сертифікатом розробника**, тому Windows покаже синє вікно «Windows захистила ваш ПК».
Це очікувано. Щоб запустити: натисніть **«Докладніше»**, потім **«Виконати в будь-якому разі»**. Код відкритий (MIT); файли релізу зібрано локально з цього коду (CI збирає такі самі артефакти);
перевірити файл можна за SHA-256 з опису релізу.

### З вихідного коду

Потрібен Node.js 22+.

```bash
npm ci
npm start          # справжній режим
npm run demo       # демо без акаунта
npm test           # тести
npm run dist       # інсталятор NSIS і portable у папці dist/
```

## Неофіційний проєкт

Human Plus створено учнем для учнів. Він не пов'язаний із HUMAN, не схвалений і не підтримується компанією. API HUMAN **недокументоване й може змінитися**;
тоді частина секцій деградує (покажемо, що вдалося), а після виправлення в `src/api.js` усе повернеться. Пропозиція команді HUMAN — у [docs/PITCH.md](docs/PITCH.md) (чернетка).

Іконку легко замінити: `build/icon.svg`. Ми свідомо не використовуємо логотип HUMAN, поки не отримали дозволу.

## Що зроблено, а що ні

Зроблено: усе з розділів вище, юніт-тести (ролі, нормалізація, межі дня за `Europe/Kyiv` із переходом часу, множина, санітизація, allowlist, контраст WCAG AA, клієнт API,
сервіс), CI, демо-режим, діагностика без даних учня.

Не зроблено або не перевірено (чесно):

- **Не перевірено на акаунті вчителя** (його немає): відмова спирається на перелічення ролей із коду фронтенду та юніт-тести `isStudent`.
- Скасування, перенесення й заміни (`cancellationLessons`, `lessonReschedules`, `replacementTeachers`, `weekends`) у тестовому акаунті порожні: розбір захисний, за кодом фронтенду; перенесення лише позначаються.
- Блок `tx03` (текст нового покоління) і `qn01`/`pl01` (питання, опитування) не підтверджені на живих даних; нерозпізнане показується повідомленням.
- Підпис «неофіційний клієнт» на сторінці входу HUMAN винесено в заголовок вікна й екран входу (накладати власний текст на чужу сторінку не стали).
- Знімки екрана зроблено без OS-матеріалу (Mica/Acrylic), тож у Windows 11 фон вікна виглядає інакше (він прозоріший).
- Значок застосунку: векторне відтворення наданої аватарки, не піксель-у-піксель оригінал; оригінал можна покласти в `build/avatar.png`.
- Збірка не підписана (SmartScreen), автооновлення немає.
- GIF-демонстрації немає (лише скриншоти). Автооновлення й підпис коду — поза v1.
- Підписи міні-режиму та скляні ефекти Windows 11 (Mica/Acrylic) бачать лише Windows 11 22H2+; на Windows 10 — суцільний фон із градієнтом.
- Однозначні спрощення: перенесення заміщень і шкільні свята позначаються лише за наявності даних; оцінки показуються за завантажений період без середніх.
