# Як Human Plus користується API HUMAN

Human Plus — **неофіційний** клієнт лише для читання. Нижче — повний перелік звернень до серверів HUMAN, їхня мета й навантаження.
API недокументоване; усе перевірено вручну на сесії власного акаунта учня.

## Принципи

- **Лише `GET`.** Жодних `POST/PUT/PATCH/DELETE`. Це перевіряється тестами (`test/service.test.js`, `test/blocks.test.js`).
- **Лише власні дані учня** і лише в межах його сесії (куки). Жодного обходу авторизації, чужих `uid` чи масового збору.
- **Прозорий `User-Agent`:** `HumanPlus/<версія> (unofficial; read-only; <контакт>)`. Ми не маскуємось під браузер.
- Не більше **4 одночасних запитів**; на `429` і `5xx` — експоненційна затримка з джитером (до 30 с) і повага до `Retry-After`;
  не більше 3 повторів на запит; після **3 збоїв поспіль** автооновлення призупиняється, і застосунок показує зрозуміле повідомлення.
- Домени, до яких можуть іти запити, перелічені в одному місці — `src/allowlist.js` — і покриті тестами.

## Ендпоінти

Усі шляхи — `https://api.human.ua/v1/{uid}/…`, де `{uid}` — id користувача з куки `last-sub-client-id`.

| Ендпоінт | Навіщо | Коли викликається |
|---|---|---|
| `system/info` | Перевірка ролі: працюємо **лише** для учня (`lmsUser.role_id === 2` тощо) | кожне оновлення, **до** будь-яких даних |
| `calendar?dateStart&dateFinish&expand=group.subject,webConference,classroom` | Уроки, розклад, зв'язок уроків із ДЗ, оцінки. **Один запит** на вікно «понеділок −2 тижні … +5 тижнів» | кожне оновлення |
| `home-task/home-task/students-tasks?filter=received` | Видані завдання ученика (точні статуси й дедлайни) | кожне оновлення |
| `…students-tasks?filter=review` | Завдання «на перевірці» | кожне оновлення |
| `…students-tasks?filter=approved` | Прийняті завдання (+ оцінка) | кожне оновлення |
| `…students-tasks?filter=rejected` | Повернуті на доопрацювання | кожне оновлення |
| `plan/theme/{theme_id}?expand=home_tasks.content,home_tasks.type,lesson_tasks.content,lesson_tasks.type` | Повний вміст ДЗ **і** матеріалів уроку (текст, посилання, файли, зображення) | лише коли користувач розгортає завдання чи урок; результат кешується за `updated_at` |
| `files.human.ua/images/…`, `files.human.ua/{uid}/file/get/{hash}` | Зображення з завдань (показуємо в застосунку) і файли (зберігаємо за явним кліком) | лише за потреби; зображення — раз на сесію |
| `calendar` для іншого тижня | Вкладка «Розклад» поза завантаженим вікном | лише при гортанні тижнів |

## Скільки запитів

| Дія | Human Plus | Оригінальний сайт |
|---|---|---|
| Запуск / оновлення | **6** (`system/info`, `calendar`, 4× `students-tasks`) | відкриття сторінки розкладу: **7** запитів до API (`system/info`, `system/tariffs`, `socket-connection-token`, `count-not-seen-messages`, `notifications`, `push/settings`, `calendar` за один день); перегляд тижня — ще 5–7 день за днем |
| Відкрити завдання чи урок | ≤ 1 на тему (далі з кешу) | кілька запитів на кожен урок |
| Автооновлення | кожні 12 хв і лише поки вікно видно; 6 запитів | — |
| Фон (вікно приховане) | 0 | — |

Висновок: один запуск створює навантаження **не більше, ніж відкриття сторінки розкладу на оригінальному сайті**; без поштучного відкриття уроків.
Кількість запитів за останнє оновлення видно в «Про застосунок» і в діагностиці («Повідомити про проблему»).

## Кеш і умовні запити

Сервер не віддає `ETag`/`Last-Modified` (`Cache-Control: no-store`), тож умовні запити неможливі. Заміна:

- вміст ДЗ і матеріалів кешується на диску й інвалідується за `updated_at` завдання;
- зображення живуть у пам'яті процесу (до 30 штук), файли ніколи не кешуються;
- показ на старті — з кешу миттєво, оновлення йде у фоні (stale-while-revalidate);
- офлайн: показуються збережені дані з позначкою.

## Захисна поведінка

- Невідома або змінена форма відповіді не валить застосунок: секції розбираються окремо, нерозпізнані потрапляють у банер і діагностику.
  Якщо `students-tasks` недоступний, статуси наближено виводяться з календаря, і про це сказано.
- Усе, що знає про формат Human, зосереджено в `src/api.js`, `src/blocks.js` і `src/normalize.js`.
